## 0. 한 줄 답

**`_7_board_test/.env` 의 `DATABASE_URL` 한 줄만 바꾸면 된다. 파이썬 코드는 손대지 않는다.**

```dotenv
DATABASE_URL=mysql+pymysql://<계정>:<비밀번호>@localhost:3306/my_new_board_db
```

`config.py` 가 이 값을 읽어 `SQLALCHEMY_DATABASE_URI` 로 넘긴다. 그게 전부다.

```python
# config.py  — 이 부분은 고칠 필요 없다
SQLALCHEMY_DATABASE_URI = os.environ.get(
    'DATABASE_URL',
    'mysql+pymysql://<user>:<password>@localhost:3306/my_new_board_db',
)
```

> **`app.py` 나 `config.py` 에 비밀번호를 직접 쓰지 말 것.**
> 코드에 적으면 깃에 그대로 올라간다. `.env` 는 `.gitignore` 대상이라 안 올라간다.

## 2. `DATABASE_URL` 뜯어보기

```
mysql+pymysql://boarduser:mypw1234@localhost:3306/my_new_board_db
└────┬─────┘   └───┬───┘ └───┬──┘ └───┬───┘ └┬─┘ └──────┬──────┘
   드라이버       계정      비밀번호     주소   포트      DB 이름
```

| 조각 | 뜻 | 바꿔도 되나 |
|---|---|---|
| `mysql+pymysql` | MySQL 을 `PyMySQL` 로 접속 | 그대로 두기 (SQLite 쓸 때만 변경 → §6) |
| `boarduser` | **MySQL 계정 이름** | ✅ 본인 것으로 |
| `mypw1234` | **비밀번호** | ✅ 본인 것으로 (특수문자 주의 → §4) |
| `localhost` | DB 주소. 내 PC면 `localhost` | ✅ 다른 PC면 그 IP |
| `3306` | 포트. MySQL 기본값 | ✅ 바꿨다면 그 번호 |
| `my_new_board_db` | **DB(스키마) 이름** | ✅ 원하는 이름으로 |

## 3. 상황별로 뭘 넣나

### ⓐ 도커 MySQL — 현재 강의 환경

지금 돌고 있는 컨테이너:

```
NAMES          IMAGE          PORTS                     STATUS
mysql-server   mysql:latest   0.0.0.0:3306->3306/tcp    Up
```

컨테이너가 `3306` 을 내 PC 로 열어두었으므로 **주소는 `localhost`** 다.

```dotenv
DATABASE_URL=mysql+pymysql://root:<컨테이너_root_비번>@localhost:3306/my_new_board_db
```

컨테이너를 **새로 만든다면** 비밀번호는 만들 때 정한다.

```powershell
docker run -d --name mysql-server -p 3306:3306 `
  -e MYSQL_ROOT_PASSWORD=<정할_비밀번호> `
  -e MYSQL_DATABASE=my_new_board_db `
  mysql:latest
```

`MYSQL_DATABASE` 를 주면 **DB 까지 자동 생성**되어 §5 를 건너뛸 수 있다.

### ⓑ 내 PC 에 직접 설치한 MySQL

```dotenv
DATABASE_URL=mysql+pymysql://root:<설치할때_정한_비번>@localhost:3306/my_new_board_db
```

### ⓒ 다른 PC / 서버의 MySQL

```dotenv
DATABASE_URL=mysql+pymysql://boarduser:<비번>@192.168.0.15:3306/my_new_board_db
```

상대 PC 에서 **외부 접속 허용**과 **방화벽 3306 개방**이 되어 있어야 한다.

### ⓓ 도커 안의 n8n 에서 이 앱을 부를 때

n8n 컨테이너 입장에서 `localhost` 는 **자기 자신**이다. 내 PC 를 가리키려면:

```
http://host.docker.internal:5000
```

## 4. ⚠ 비밀번호에 특수문자가 있으면 — URL 인코딩 필수

`DATABASE_URL` 은 주소(URL) 형식이라 `@ # / : ?` 같은 글자가 **구분자로 먼저 해석된다.**
에러가 나면 차라리 낫고, **조용히 엉뚱하게 잘려서** 원인 찾기가 어렵다.

비밀번호가 `p@ss#1` 인 경우를 실제로 파싱해 보면:

```
인코딩 안 함 -> user: boarduser | password: p | host: ss#1@localhost | db: my_new_board_db
인코딩 함    -> user: boarduser | password: p@ss#1 | host: localhost  | db: my_new_board_db
```

**비밀번호가 `p` 하나로, 주소가 `ss#1@localhost` 로 잘못 잡혔다.** (에러 메시지도 안 나온다)

### 변환표

| 문자 | 바꿔 쓸 것 | | 문자 | 바꿔 쓸 것 |
|---|---|---|---|---|
| `@` | `%40` | | `/` | `%2F` |
| `#` | `%23` | | `?` | `%3F` |
| `:` | `%3A` | | `%` | `%25` |
| `&` | `%26` | | 공백 | `%20` |

### 변환값 구하는 명령

```powershell
python -c "from urllib.parse import quote_plus; print(quote_plus('p@ss#1'))"
# p%40ss%231
```

```dotenv
DATABASE_URL=mysql+pymysql://boarduser:p%40ss%231@localhost:3306/my_new_board_db
```

> **가장 쉬운 해결책**: 실습용 비밀번호는 **영문·숫자만** 쓰는 것. 인코딩 고민이 사라진다.

## 5. DB 와 계정 만들기 (MySQL)

### ⚠ `db.create_all()` 은 **표**만 만든다. **DB(스키마)는 안 만든다.**

`my_new_board_db` 가 없으면 접속 자체가 실패한다. **먼저 만들어야 한다.**

### 도커 MySQL 에 접속

```powershell
docker exec -it mysql-server mysql -u root -p
```

### DB 만들기

```sql
CREATE DATABASE my_new_board_db
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

`utf8mb4` 를 꼭 줄 것 — 한글과 이모지가 깨지지 않는다.

### 본인 전용 계정 만들기 (권장)

`root` 를 그대로 쓰면 실수로 다른 DB 까지 지울 수 있다. 실습용 계정을 따로 만든다.

```sql
CREATE USER 'boarduser'@'%' IDENTIFIED BY '<비밀번호>';
GRANT ALL PRIVILEGES ON my_new_board_db.* TO 'boarduser'@'%';
FLUSH PRIVILEGES;
```

| 부분 | 뜻 |
|---|---|
| `'boarduser'@'%'` | 어느 주소에서 접속하든 허용 (`'localhost'` 면 그 PC 에서만) |
| `ON my_new_board_db.*` | **이 DB 안에서만** 권한. 다른 DB 는 못 건드린다 |

만든 뒤 `.env` 를 바꾼다:

```dotenv
DATABASE_URL=mysql+pymysql://boarduser:<비밀번호>@localhost:3306/my_new_board_db
```

### 비밀번호만 바꾸고 싶을 때

```sql
ALTER USER 'boarduser'@'%' IDENTIFIED BY '<새_비밀번호>';
FLUSH PRIVILEGES;
```

바꾼 뒤 **`.env` 의 `DATABASE_URL` 도 같이 고쳐야** 한다. 안 고치면 `Access denied` 가 난다.

## 6. MySQL 없이 실습하기 — SQLite

MySQL 설치가 막혔을 때, `.env` 한 줄만 바꾸면 **설치 없이** 돌릴 수 있다.
파이썬에 내장돼 있어 추가 설치가 필요 없다.

```dotenv
DATABASE_URL=sqlite:///board.db
```

`_7_board_test` 폴더에 `board.db` 파일 하나가 생기고, 표도 똑같이 만들어진다. 실제로 확인한 결과:

```
접속 대상: sqlite:///.../board.db
만들어진 표: ['posts', 'security_events', 'users']
security_events 컬럼 13 개
```

| | MySQL | SQLite |
|---|---|---|
| 설치 | 필요 | 불필요 (파일 1개) |
| 여러 명 동시 접속 | 강함 | 약함 |
| 용도 | 정식 실습·제출 | 급할 때 임시 |

> 제출·채점 환경이 MySQL 이라면 **최종 확인은 반드시 MySQL 로** 할 것.

## 7. 확인 방법

> ### ⚠ 아래 명령은 **반드시 `_7_board_test` 폴더 안에서** 실행할 것
>
> `python -c "..."` 는 파일이 없는 실행 방식이라, python-dotenv 가 `.env` 를
> **스크립트 위치가 아니라 현재 폴더(cwd) 기준**으로 찾는다.
> 상위 폴더에서 실행하면 엉뚱한 `.env` 를 읽어 **설정이 통째로 무시**된다.
>
> ```
> cwd = ...\Python-Lab-ALeph-T        → find_dotenv: ...\Python-Lab-ALeph-T\.env   → DATABASE_URL 읽힘? False
> cwd = ...\Python-Lab-ALeph-T\_7_board_test → find_dotenv: ...\_7_board_test\.env → DATABASE_URL 읽힘? True
> ```
>
> 잘못된 폴더에서 실행하면 이런 에러가 난다 — **비밀번호를 고쳐도 해결되지 않는다.**
>
> ```
> Access denied for user '<user>'@'172.17.0.1' (using password: YES)
>                         ~~~~~~ config.py 의 기본값이 그대로 쓰인 것
> ```
>
> 계정명이 `<user>` 로 나오면 **`.env` 를 아예 못 읽은 것**이다. 폴더부터 확인할 것.
> (`python app.py` 로 실행할 때는 파일 기준이라 이 문제가 없다.)

### 지금 어디에 붙어 있나

```powershell
cd E:\0-Aleph-Python-Test\Python-Lab-ALeph-T\_7_board_test
python -c "from app import app; print(app.config['SQLALCHEMY_DATABASE_URI'])"
```

> ⚠ 이 명령은 **비밀번호가 그대로 화면에 찍힌다.** 화면 공유·캡처 중이면 실행하지 말 것.

### 비밀번호를 가린 채 확인 (공유해도 안전)

```powershell
python -c "from app import app; from sqlalchemy.engine import make_url; u=make_url(app.config['SQLALCHEMY_DATABASE_URI']); print(f'{u.drivername} | {u.username}@{u.host}:{u.port}/{u.database}')"
```

### 접속·계정·DB 한 번에 확인

```powershell
python -c "from app import app; from extensions import db; from sqlalchemy import text; app.app_context().push(); s=db.session; print('계정:', s.execute(text('SELECT CURRENT_USER()')).scalar()); print('DB  :', s.execute(text('SELECT DATABASE()')).scalar())"
```

## 8. 자주 나는 에러

| 에러 메시지 | 원인 | 해결 |
|---|---|---|
| `Can't connect to MySQL server ... (10061)` | MySQL 이 안 떠 있음 | `docker start mysql-server` |
| `Access denied for user '...'@'...'` | 계정·비밀번호 틀림 | `.env` 의 `DATABASE_URL` 확인 |
| `Access denied` (비번은 맞는데) | 비밀번호 특수문자 미인코딩 | §4 참고 |
| `Unknown database 'my_new_board_db'` | **DB 를 안 만듦** | §5 의 `CREATE DATABASE` |
| `No module named 'MySQLdb'` | 드라이버 표기 오류 | `mysql://` → **`mysql+pymysql://`** |
| 한글이 `???` 로 저장됨 | DB 문자셋이 `utf8mb4` 아님 | §5 대로 다시 생성 |
| `.env` 를 고쳤는데 반영이 안 됨 | 서버가 옛 설정으로 떠 있음 | 앱 **재시작** (`Ctrl+C` 후 다시 실행) |
| 값이 계속 `None` | `.env` 를 다른 위치에서 읽음 | `python -c "from dotenv import find_dotenv; print(find_dotenv())"` |
| 계정명이 **`<user>`** 로 나오며 `Access denied` | `.env` 를 아예 못 읽어 `config.py` 기본값이 쓰임 | **`_7_board_test` 폴더에서** 실행 (§7 경고 참고) |

### 함정 — 시스템 환경변수가 `.env` 를 이긴다

`load_dotenv()` 는 **이미 있는 환경변수를 덮어쓰지 않는다.**
예전에 `set DATABASE_URL=...` 로 설정해 둔 게 있으면 `.env` 를 아무리 고쳐도 그게 먼저 먹는다.

```powershell
# 현재 환경변수에 잡혀 있는지 확인 (비어 있어야 정상)
echo $env:DATABASE_URL
```

## 9. 보안 수칙 (제출 전 확인)

| | 지킬 것 |
|---|---|
| ✅ | 비밀값은 **`.env` 에만** 적는다 |
| ✅ | `.env.example` 에는 **키 이름과 자리표시자만** (`<비밀번호>`) |
| ✅ | 제출·공유 시 `.env.example` 만 포함 |
| ❌ | `.py` 파일에 비밀번호 직접 쓰기 |
| ❌ | `.env` 를 깃에 커밋 |
| ❌ | 문서·발표자료·스크린샷에 실제 비밀번호 노출 |

### `.env` 가 깃에 안 올라가는지 확인

```bash
git check-ignore -v .env
# .gitignore:1:.env    .env      ← 이렇게 나오면 정상

git ls-files | grep "\.env$"
# 아무것도 안 나와야 정상
```

### 실수로 커밋했다면

지우고 다시 커밋해도 **과거 기록에 남는다.** 비밀번호를 **즉시 변경**하는 게 먼저다.

```sql
ALTER USER 'boarduser'@'%' IDENTIFIED BY '<새_비밀번호>';
```
